# Changelog

## 0.11.2
- Helium is the default browser (Chromium based; package `helium-browser` from the official release, signature checked at build): Dock, Spotlight web search, default apps for web links and pages, privacy defaults (no usage reports, surveys or sign-in prompts), video decode on the GPU. Firefox stays in the App Store.
- WolKernel 1:1.0+7.3-2: services with a syscall filter no longer log an audit warning on every boot when audit is on. WolOS boots with `audit=0` (it ships no audit tools or audit-based security module).
- libwol, the app API (ADR 0020, archicture/modules/abi.md): `wol.h` and `libwol.so.1` for apps in any language, with a stable C ABI (versioned symbols; a test fails on any removed or changed symbol or declaration). First calls: version, errors, strings, an event loop any language can drive (fd + dispatch) with subscriptions to system events, system facts (OS, kernel, appearance, accent), posting notifications, and window content built from stacks, labels and buttons with click callbacks. The desktop draws app windows with Kit parts and shows app notifications as banners, with their buttons. Apps ask WolOS for services; WolOS checks the app's permission, and Settings > Privacy & Security lists and switches Notifications like the other permissions. No telemetry: libwol talks only to WolOS itself.
- libwol 1.1: rows, lists, spacers, text fields, toggles, sliders and images; changing a part's text or value redraws its window; apps hear when the person edits, toggles, slides or closes; notifications with up to three buttons, and a pressed button reaches only the app that posted it. Apps built for 1.0 keep working unchanged.
- libwol 1.2: window menus and toolbars (keys come back to the app; a shortcut like `cmd+s` works in the window), and an app can replace or withdraw a notification it posted, which only the process that posted it can do.
- libwol 1.3: clipboard text (`wol_clipboard_copy_text`, `wol_clipboard_set_text`), behind two new permissions in Privacy & Security. wold checks the app, then asks the desktop of its account.
- libwol 1.4: an app keeps its own preferences (`wol_prefs_`), held by wold per account and executable so no app can reach another's, and service answers arrive as one read-only tree (`wol_info_`).
- libwol 1.5: file panels (`wol_panel_open`, `wol_panel_save`). The person picks, and the app gets that one file already open, never a path.
- libwol 1.6: battery and Low Power Mode facts (`wol_power_copy_info`), and `wol_power_keep_awake`, which lasts as long as the app does.
- libwol 1.7: whether the computer is online and over what (`wol_network_copy_info`), never an address or a network name.
- libwol 1.8: read the volume and what is playing (`wol_audio_copy_info`) and change the volume or mute (`wol_audio_set_volume`, `wol_audio_set_muted`), behind separate permissions.
- Lua desktop widgets (runtime): one `.lua` file (layout, data, refresh, click handlers) becomes a Kit view tree, reloaded when the file changes; an example Clock ships with it. Scripts run sandboxed (no files, programs or network) and reach only the services they declare. The desktop runs them from `~/.config/wolos/widgets/` (`wol widgets add lua:clock`), on the same calm timer as the other widgets.
- Package mirrors (ADR 0019): `[wolos]`, then `[wolos-cachy]` (x86-64-v3 builds of the same Arch versions, frozen at each release, on only on CPUs that run them), then Arch at the release date. `wol mirror status|rank|gate|kernel`; `wol update` moves all three repos together.
- One picture from power-on to the desktop (ADR 0012): the WolOS mark replaces the loader's kernel splash, boot text never reaches a video console (rc.d `wolos_quiet`; serial consoles stay readable), every compositor starts black and every first window fades in from black and out to it. One account: its session starts directly behind the lock screen (no login window hop). The Hyprland fork hides the desktop under a lock taken over at boot or after a crash; `wol-lock` respawns a crashed lock screen and never unlocks on its own; Ctrl+Alt+Fn cannot show a console. The start-up lock opens the login keyring. `grep wolos-boot /var/log/messages` lists each boot stage with its time. If passwords can't be checked, the lock screen says so and offers Restart.
- Setup Assistant, redone (ADR 0013): the Welcome art, then four questions on one card each: Language & Region (language and keyboard on one page, guessed from the time zone and console keymap; the keyboard applies at once, so the password is typed on it), Wi-Fi (scanned by wol-login, skipped on a wired machine, a wrong password says so), Create Your Account (full name fills the account name; colour for the avatar; administrator with zsh and sudo), Appearance (Light, Dark or Auto, and three looks), then You're All Set and Get Started fades into the desktop. Return continues, Escape goes back; every problem is one sentence on the page that has it.
- Install WolOS is an app (ADR 0013): pick the disk by name and size, a clear erase warning, Erase and Install, progress with the Pocket Watch, the step it is on and the time left (the screen stays on and closing the lid does not sleep the machine meanwhile), then Restart into Setup. It runs the boot menu's installer without a terminal or a password (the live user may run `libexec/wolos/install-run` with sudo): GPT with EFI and BIOS boot, ZFS with boot environments, the system, the boot loader, the apps. Each step reports `wolos-install: <stage> <percent> <message>`; a stop says where it stopped, cleans up and offers Try Again.
- Error copy in one place (`shell::copy`, archicture/modules/ux-journeys.md): every failure sentence says what happened and what to do; `tests/copy_lint.rs` bans raw error text (errno, exit codes, paths, program names, "failed") and `{e}` outside logs. Fixed: Software Update said "Make sure pkg is installed"; App Store said "X was not installed. The change did not work"; auth messages without a full stop.

- Hardware (archicture/modules/hardware.md): one catalogue picks driver, firmware, packages and loader lines per device (CPU, GPU, Wi-Fi, Ethernet, Bluetooth, audio, webcam, I2C touchpads, card readers, backlight). `wol hw` lists devices and their state (ready, needs driver, needs firmware, unsupported) with a one-line hint; `wol hw status` shows problems only; `wol hw fix` loads missing modules through wol-admind (`hw-load`, catalogue modules only) and installs missing packages with `--yes`. New rc.d `wolos_hw` (before netif) runs `wol hw boot` every boot: loads the modules, writes next-boot loader lines (early CPU microcode, RTL8125/8126 driver, NVIDIA modeset) and publishes `/var/run/wolos-hw.json`; `wolos_wifi` and `wolos_gpu` no longer pick drivers, and machines without Wi-Fi skip the 10 s wait.
- Offline repo adds CPU microcode (Intel 31.5 MB, AMD 0.6 MB), Bluetooth firmware (Intel, Realtek, Broadcom), RTL8125/8126 Ethernet, USB cameras (webcamd, started on plug-in, `/dev/video*` for group video) and PipeWire on sound(4); all GPU firmware comes with drm-kmod. NVIDIA is detected and installed online (~520 MB).
- powerd runs only where cpufreq can steer the CPU (not with Intel HWP or in a VM, where it failed at boot); `wol hw boot` alone decides (rc.conf no longer enables it). `wol sys hw` gives the hardware list as a System API topic. ntpd refreshes the leap-second file and re-resolves its pool once DHCP has a lease. Desktop tunables, each commented: scheduler preemption threshold 224, user mounts, no keyboard debug keys, `cuse` at boot.
- Low Power Mode works on Speed Shift CPUs (powerd off there): wol-admind `power-mode` sets the energy preference on every CPU (`dev.hwpstate_intel.N.epp`, kept in `/etc/sysctl.conf.local`) and the powerd flags only where powerd runs; the switch reads the preference first and hides when there is nothing to steer.

Services start or stop only when not already so; `Controls::admin_request` sends any of them.

Administrator changes ask for the password every time and run in the shell, never in the helper. Requests queue (4 waiting at most); no answer in 50 s is a no; without a session nothing changes. One audit record per call.
- `.wol` app packages (ADR 0011, archicture/modules/packages.md): one file holding `Info.json`, a pkg(8) package and a SHA-256 manifest, signed with Ed25519. `wol install <file.wol|app|package>`, `wol remove`, `wol list`, `wol search` (App Store catalogue and the package index), `wol update apps`. wol-admind `wol-install` verifies its own copy, installs dependencies from FreeBSD pkg and `pkg add`s the payload after a restore point; an unsigned package needs the password every time, a bad signature or hash is refused. `wol-remove` deletes the package and dependencies nothing else uses. Packages and the index come from github.com/wonderlandos/wol-packages.
- WolKernel (kernel/README.md): the kernel is named WolKernel in `uname -i`, About and the boot menu; `uname -s` stays FreeBSD (pkg ABI, ports, Linux ABI). First boot installs it online and loads it with modesetting (`wol hw boot --online`; tunables set with kenv before the module loads), so the first login already runs on it. The session names only installed NVIDIA libraries (GBM, GLX, VA-API `nvidia-drm`; was `nvidia`, a driver that does not exist); `wol-realtime gpu offload` prints one app's PRIME offload environment; render nodes are matched to GPUs by PCI id, so driver load order no longer swaps them. No system shortcut takes a plain ⌘ letter any more (Control Center, Notifications, Files, light/dark and lock had ⌘A/N/E/⇧T/L; tiling float is ⌥⌘F). Settings > Keyboard Shortcuts lists the App commands group.
- Notification banners leave with Esc or a swipe; Esc closes Notification Center. Banners show an app's buttons (two at most, e.g. Restart after a driver install) and stay until one is chosen; a click on the banner runs the app's default action. System notices carry the WolOS mark.

## 0.11.1
- Login window and Setup use the GTK cairo renderer (no GPU renderer dependency before login); wol-shell stderr goes to `$XDG_RUNTIME_DIR/wol-shell.log`; the console no longer forces 1920x1080 (panel native mode).
- Wi-Fi (archicture/modules/wifi.md): offline repo ships Intel iwlwifi (7000..sc, incl. ax210 for ADL CNVi 8086:51f0), Realtek rtw88/rtw89, Qualcomm ath10k/ath11k and MediaTek mt7921/7925 firmware (~21 MB). New rc.d `wolos_wifi` (before netif, every boot): loads the driver for the wireless NIC present, creates `wlan0` on the first `net.wlan.devices` entry, creates `/etc/wpa_supplicant.conf` if missing and sets `ifconfig_wlan0="WPA DHCP"` if unset, so Setup Assistant and Control Center Wi-Fi have an interface.
- First real-GPU session fixes: GTK apps use the cairo renderer (`GSK_RENDERER=cairo`; the default renderer never mapped the shell, Setup or login windows on the passthrough iGPU); foot config uses `[colors-dark]` (foot 1.28 rejects `[colors]`) and JetBrains Mono; fontconfig maps `monospace` to JetBrains Mono (it resolved to Font Awesome).
- Login and Setup screens: no Hyprland banners (guiutils missing, launched without start-hyprland); seen on the first real-GPU boot.
- Installer never offers the boot media: `libexec/wolos/install-disks` skips disks holding ufs/FreeBSD_Install, iso9660/WOLOS or a Ventoy stick (msdosfs/VTOYEFI), plus cd/md (the Ventoy stick was eligible).
- Live ISO (ADR 0009): the default boot is the WolOS desktop, autologin as `live`, all writes in memory (rc.d `wolos_live`: tmpfs unionfs over /etc, /usr/local/etc, tmpfs /home). "Install WolOS" in the dock runs the unattended installer; the old installer console needs `set wolos.install=1` at the loader prompt.
- wolos_gpu: a panel backlight left at 0 after the driver loads is raised to 80 (passthrough boot ran the whole desktop on a dark panel); a non-zero level is never changed.
- i915 fork patch 0002: when no VBT is found (firmware param, OpRegion, ROM), i915 loads `/boot/firmware/i915/vbt.bin` if present. A VFIO-passed-through laptop iGPU gets no OpRegion under OVMF, so the eDP panel stayed black; copy the host VBT (`/sys/kernel/debug/dri/*/i915_vbt`) there. Real hardware never reaches the fallback.
- Compute and power limits (archicture/modules/intel-graphics.md): `wol-realtime power show|set --pl1 W --pl2 W` reads/writes Intel RAPL package limits (MSR 0x610; refuses a locked MSR). `vkpeak` ships for Vulkan compute and GPU bandwidth peaks (no Intel OpenCL runtime on FreeBSD). `verify-gpu.sh` runs it and A/B's PL1 firmware vs 15 W.
- Memory bandwidth (ADR 0007 accepted, archicture/modules/memory-bandwidth.md): wol-hypr records every frame (time, damaged px) in a realtime ring; `wol-realtime hypr stats` prints p50/p95 µs, damage %, full-screen frames and derived bytes/frame. `wol-realtime gpu caps|sample` prints GPU freq range, FBC state and RAPL graphics energy (i915: lindebugfs + cpuctl; other drivers: nulls). Firefox decodes video with VA-API by default.
- i915 driver fork (ADR 0008, kernel/drm): drm-kmod drm_v6.12.85_3 + patch: a request still running at its vblank deadline is boosted (`set_deadline`), waitboost only for the frontmost process (`compat.linuxkpi.i915_wol_waitboost=2`, pid from wold). Ships as `drm-fork.tar` over pkg drm-612-kmod (locked). `verify-gpu.sh` gains A/B runs (waitboost, deadline boost, INTEL_DEBUG=noccs) with RAPL watts per side.
- build-in-vm: copy-back is resumable and sha256-verified (`image/vm/fetch.sh`; a 3.5 GB `ssh cat` once stopped at 2.8 GB).
- Menu bar with no focused window shows no app name and no app/Window menu (was "Files", an app that was not running). Switcher fails closed: it does not open when the compositor does not answer or no window is open (drew "No open windows" over an open window when the Hyprland query failed).
- Intel graphics (archicture/modules/intel-graphics.md): the offline repo ships i915 DMC/GuC/HuC firmware (gpu-firmware-intel-kmod-alderlake, tigerlake, rocketlake, meteorlake), VA-API iHD (libva-intel-media-driver), vulkan-loader and proof tools (mesa-demos, vulkan-tools, libva-utils, glmark2, vkmark). `/boot/loader.conf.d/wolos-i915.conf` pins the i915 "unsafe" params at driver defaults (GuC off: FreeBSD shutdown hang). `wol-session` now sources `wol-realtime gpu env` (AQ_DRM_DEVICES; `LIBVA_DRIVER_NAME=iHD` on i915/xe). `image/hw/verify-gpu.sh` (also `/usr/local/libexec/wolos/verify-gpu.sh`) writes the native-boot report to /var/log/wolos-gpu-report.txt. test-install.sh uses a scratch `install.raw` and never deletes a kept `disk.raw`.
- wol-run: Proton output redirected to a file was lost (Proton ntdll closes seekable std handles). Proton targets now relay seekable stdout/stderr through pipes (`tests/relay.rs`). `image/vm/test/compat.sh --iso` packs the compat run for the installed disk.
- Icons: no SVG `<filter>` in design/icons (grey shadow box behind Files/Notes in GTK, Qt, Firefox).
