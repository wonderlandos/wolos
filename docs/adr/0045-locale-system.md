# 0045 - One locale system for the whole OS
Status: accepted (lead's goal of 2026-11-03: an optimised locale system for libwol, libwolkit, apps and system text; implemented by I18N-os and I18N-os-2). Builds on 0020 (libwol), 0036 (Crystal userland) and 0039 (libWolkit); STANDARDS §1 (every sentence lives in the copy modules) stays.

Context: every sentence the shell shows is English, written in Rust copy modules (`crates/shell/src/copy*.rs`). The lead wants WolOS in ten languages (English, Brazilian Portuguese, Spanish, French, German, Japanese, Korean, simplified Chinese, Indonesian, Tagalog) in the shell, libwol, libwolkit, Crystal apps and system text, with no cost at run time and no layout that breaks when a language is longer. Translators are not programmers and the translation itself is a separate pass with strict per-language rules, so the system must come first and must make a wrong translation fail the build, not ship. A JSON catalog would be parsed and allocated at start; a classic message-catalog file would still have to be compiled, carries its plural rules as program text and has no place for a length budget.

Decision:
- **TSV source files, edited by translators.** A unit (the shell, an app, libwol) has a directory `locale/<unit>/`: `en.tsv` (key, English, comment for the translator, length budget) and one `<lang>.tsv` per language (key, the English it was last synced with, the translation, the hash of the English it translates). English is the source; a language file is created and kept in step by `wol-i18n sync`. Tabs, line breaks and backslashes inside a field are escaped; `#` starts a comment. The format is `crates/shared/src/i18n/tsv.rs`; the translator's guide is `docs/l10n/README.md`.
- **Compiled at build into `.wtx` tables.** `wol-i18n compile` (and the shell's `build.rs`) turns a unit into one `.wtx` table per language: a header, a hash-slot index of the key names, offsets and lengths, and the UTF-8 text, all little-endian (`crates/shared/src/i18n/wtx.rs`). The build checks every rule a translation must keep and fails with file and key: the same `{placeholders}` as the English, no plural form the language does not use, within the key's length budget (columns, a wide East Asian character counts two). Warnings do not fail: a translation made for an older English (stale hash), a missing plural form.
- **Constant-time lookup, no parsing and no allocation at run time.** A table is validated once when it is loaded (every range inside the text and on a character boundary); a lookup then reads one slot and returns a `&str` slice of the table. A key is an index into the unit's English table: Rust gets a generated `Key` constant per string (`compile::keys_rs`), so a misspelt key is a compile error; Crystal, C and Lua find a key by name once (`Catalog::find`, `wolkit_catalog_find`) and keep the number.
- **Fallback chain language, then English.** `Catalog::text(key, lang)` walks `Lang::chain()` (`pt-BR -> en`, `zh-Hans -> en`); English holds every key, so a lookup always finds text, and a key a broken table lacks reads as the empty string, never a panic. A language pack can add a `<unit>.<lang>.wtx` file without a rebuild (`Catalog::load_dir`).
- **Plurals follow CLDR.** A plural key is several rows, `name#one`, `name#other` (and `many` for Spanish, French and Portuguese millions); the count picks the form with the language's rule (`plural.rs`). Japanese, Korean, Chinese and Indonesian have `other` only.
- **The pseudo-locale `xx`.** Every string accented, 40 % longer and in brackets (`[Ŀåñĝüåĝé ~~]`), placeholders kept, never offered in a menu. A golden of a pane in `xx` (`crates/shell/tests/golden_cases/locale.rs`) fails the layout check when a row no longer fits and shows at once any sentence still written in the code. A length budget in `en.tsv` must leave room for the 40 %; `wol-i18n budgets` reports, per key, the budget, the English and pseudo columns and the widest translation written so far.
- **One implementation, three doors.** `shared::i18n` (BSD-2-Clause, `crates/shared`) holds the tables, the lookup and the language rules. The shell uses it directly (`crates/shell/src/i18n.rs`). libWolkit exports it in a new symbol version `WOLKIT_1.1`: `wolkit_catalog_load`, `_load_dir`, `_retain`, `_release`, `_count`, `_find`, `_text`, `_plural` and `wolkit_lang_parse`, `_tag`, `_get`, `_set` (`crates/wolkit/src/ffi/catalog.rs`, `include/wolkit.h`), so Crystal and Cryswol apps read the same tables; the wolkit shard wraps them (`Wolkit::FFI::Catalog`) and its DSL gets `t("key")` and `t("key", n: 3, name: "x")`, which reads a language signal and so relabels a live view. libWolkit's version becomes 1.1.0 and `abi/wolkit-1.1.symbols` and `abi/wolkit-1.1.h` record the new surface.
- **The language is chosen in three places, one setting.** `Lang` is the process's language (`shared::i18n::set_lang`). The first-run Setup's Language & Region step and Settings > General > Language & Region (`ui/setup.rs`, `ui/settings/language.rs`) call `shell::i18n::set_lang` when the person picks a language, and surfaces that keep text on screen relabel through `shell::i18n::watch` (Settings builds its panes again). The choice is saved as the account's locale and the desktop pref `language`, which becomes the session's `LANG`; at start `shell::i18n::init` reads `WOL_LANG`, `LC_ALL`, `LC_MESSAGES`, `LANG`. A locale WolOS has no translation of (`it_IT`, `zh_TW`) reads English.
- **Migration in steps, each shippable.** (1) English is extracted from the existing copy modules: `sources.tsv` names the Rust files and `wol-i18n extract` writes `en.tsv` from their `const NAME: &str` items (the `///` lines become the translator's comment, a line `budget: N` the budget); the module stays the place a developer edits and a build that finds `en.tsv` out of date stops. (2) Surfaces read `i18n::t(keys::…)` instead of the constant: done for the sentences of Settings > Sound and Modules. (3) Labels, titles and sentences built with `format!` move into copy modules and become `{name}` templates by hand: done for Settings > Sound and the Control Center, the two proof panes; `docs/l10n/README.md` lists the rest with counts. (4) Translations arrive gradually, one language at a time (pt-BR, fr, ja, zh-Hans, es, de, ko, id, tl, after English is debugged), each by its own translator under its own written rules (`docs/l10n/RULES-<lang>.md`), and `wol-i18n status` gates them.

Consequences: a new language is a new `<lang>.tsv` and no code; a translator cannot break the build with anything but a rule the build states. The English stays authoritative and the copy lint (`copy::lint`) still checks it. The cost is a build step and a build dependency of the shell on `shared` (a workspace crate, no new third-party code), an ABI minor version for libWolkit, and a discipline: no sentence in a surface, only a key. Until step 3 is done for a pane its labels and titles stay English and only the sentences in the copy modules translate; `xx` shows exactly which. Length budgets are set per key as panes are migrated (the Sound subtitles first); a key without one is reported by `wol-i18n status`. Tables are small: the shell’s unit today (111 keys) is 8,017 bytes in English and 11,772 bytes in `xx`.
