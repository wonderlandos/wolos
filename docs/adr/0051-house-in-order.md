# 0051 - 0.13: put the house in order before adding anything
Status: proposed (lead rules 2026-11-04 06:20Z: every finding fixed in 0.13 is proven; 06:58Z: the classes become standards with an enforcement; 06:59Z: every finding keeps its own regression test). The CTO accepts it when Step 0 of the fix plan has merged. Builds on the two-pass rule (docs/STANDARDS.md section 8) and the rule catalogues (docs/RULES.md).

## Context
The QA-100 audit of 0.12.1 registered 990 distinct findings. The root-cause analysis groups 948 of them (95 %) into 44 classes; 42 stay singletons. Most classes are one habit repeated: a control that shows a value before the system confirmed it, a failure collapsed to a bool, a fact defined twice, a fixed size larger than a small screen, a document that describes intent instead of the tree. Fixing the 990 one by one would leave the habits in place, and the next release would bring the same rows back. Integration had also drifted from the release: the integration branch did not descend from the 0.12.1 tag, so "fixed" meant "fixed somewhere".

## Decision
**Motto (Qíjiā): "Put the house in order."** 0.13 adds nothing new except the separate tracks the lead named; it closes the classes, then the findings, then measures.

### 1. The proof rule
- A finding closes only with a **proof**: a regression test (unit, golden, journey) or an enforced rule (a `rules_*` test) that fails on the tree before the fix and passes after it. The fixer attaches the red run.
- The registry has a `proof` column. Its value is `class:RC-nn::<test>` when the class rule is the proof, or `<file>::<test>` for the finding's own test. No proof, no close; a row marked fixed without a proof reopens.
- A standard exists only with a green, ratcheting gate that runs on every push. A rules test starts with a `BASELINE` row for the debt of the tree on the day it lands, so it is green and goes red on any new violation; each row names the brief that brings it down, and a row is only ever lowered.

### 4. Wave gates
Order: Step 0 (integration descends from 0.12.1, the release gate, RU-089 baselined), then Wave A (the first day), Wave B (system integrity and security), Wave C (apps and tooling), Wave D (design rules, screens, shadow tests, journey wiring, record truth). Within a wave every brief owns a disjoint file set. A wave merges only when its gate is green on the forge:

| Gate | Runs | Passes when |
|---|---|---|
| after Step 0 | `cargo test --workspace`, the goldens, every `rules_*` test (`rules_rc_*` included), `docs_truth`, `architecture`, `unsafe_ratchet`, the installer layouts, the automatic install to its first checkpoint, the whole `qa100-*` and `qa-*` journey set | the suite and the release gate are green; the journey baseline (which fail today) is recorded |
| after A | the above, the journeys of the A proofs, the layout run, the live re-test of the first-day rows on a fresh image built from the integration branch | every A proof is green, no row reopens, every A row has its proof |
| after B | the above, the update, system-fault, network, web app and session journeys, the security re-check against the integration branch, the web header test against the deployed hosts | every B proof is green, the security re-check reopens nothing |
| after C | the above, the Store, Doctor, Setup and device journeys, the manual verb gate, the web kit tests, the shell language tests if it ships | every C proof is green, the manual re-check finds no false claim on a published page |
| after D (release gate of 0.13) | the full golden matrix at every size and scale, every rules test with its baseline printed and no row higher than before, every `qa100-*` journey wired in CI and green, the shadow coverage targets | the lead signs the release checklist; then the final release plan (bench against the baseline, packages, the full image) |

At each gate the registrar re-reads the registry; a row moves to fixed only with a proof that was red before the brief's first commit and green after it. Each wave's closing worker lowers the `BASELINE` rows its briefs brought down.

## Consequences
- 0.13 ships later than a feature release would and with fewer new things; every closed row stays closed, because its class has a gate.
- Briefs get smaller: the shared helper (the pending control, the reason enum, the one fact, the clamp, the supervisor, the view helper, the live model, the queue) is written once and the rule forbids the local copy.
- The ratchets carry debt openly: a baseline row is a debt with an owner, printed on every run, and only ever lowered. A rule red on its first day would unguard the rest of its file, so no rule lands without its baseline.
- A rule that scans text can miss a case or flag a false one. A false hit is fixed in the scanner with a self-test (each `rules_rc_*.rs` has one), never by raising a row.
- The class ids RC-nn are anchors of this record and of docs/STANDARDS.md section 9; the enforced rules use the new RULES.md prefix RH- because RC- is already the CI catalogue.
