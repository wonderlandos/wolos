# 0063 - Atlas Drive: browser automation for Atlas, built for AI agents
Status: accepted (lead orders 2026-11-04 06:18Z "design our own automation and devtools", 07:14Z "faster and more efficient than Playwright", 2026-11-05 04:02Z "more fast, more enhanced, better for AI on tokens and contexts" and 04:10Z "no permission spam"). Design of record: `.claude/v012/atlas/automation-design.md` (option A of its three protocol options); numbers in [bench/atlas-drive.md](../bench/atlas-drive.md); module page [modules/atlas-drive.md](../modules/atlas-drive.md). Builds on 0043 (Atlas: peer identity, no port in the product) and 0020 (helpers, `wol mcp`, the gate).

## Context
WolOS tests Atlas, the hub and the OS web apps with pixel steps (wolvm journeys), and an AI agent that wants to use a browser today gets Playwright: a Node process of 160 MB that returns nothing after an action, and a page dump of 100 000 tokens when it asks what is there. Atlas is Chromium: every capability we need (accessibility tree, tracing, memory counters, network log, emulation) is the DevTools Protocol (CDP). The engine can speak it over `--remote-debugging-pipe` (descriptors 3 and 4 of the browser, no port).

## Decision
1. **CDP over the pipe, exposed on a Unix socket.** `atlas-drive serve` launches Atlas with `--remote-debugging-pipe` (headless by default) and listens on `$XDG_RUNTIME_DIR/atlas/drive.sock` (directory 0700, socket 0600). The socket carries CDP messages unchanged, `\n`-framed, so any CDP client works after an `AF_UNIX` connect (raw pass-through, ids rewritten per client), plus the `Drive.*` verbs. The crate refuses any `--remote-debugging-port/-address` argument (`browser::forbid_debug_port`, tested); the product launcher never passes one. WebDriver BiDi and an in-page agent stay rejected (design section 2). Option A was not reopened.
2. **One Rust crate, `crates/atlas-drive`**, GPL-2.0-or-later, daemon + client library + CLI + MCP server, threads and no async runtime, dependencies `shared` and `serde_json` only (architecture test row), `#![forbid(unsafe_code)]` (unsafe ratchet row 0): std cannot place a child's descriptors, so the browser is started as `sh -c 'exec "$0" "$@" 3<&0 4>&1 0</dev/null 1>/dev/null'` with the pipes as its stdin and stdout; the shell moves them to 3 and 4 and execs the browser. A fuzz target (`atlas_drive_wire`) covers the framers, a batch plan, the grants file, the accessibility tree and source maps.
3. **The stable surface is the verbs, not the raw methods.** About 50 `Drive.<verb>` calls (spec.rs is the one table: dispatcher, `--help-agent`, MCP manifest, docs). The raw CDP subset the verbs use is frozen in `subset.rs` (77 methods, 30 events; 79 methods after round 2) and `tests/subset.rs` scans the sources both ways, so a Chromium major that drops a method is found when the lane runs, and journeys depend on verbs.
4. **Built for the model, measured in tokens.**
   - `snapshot` is the accessibility tree flattened to one line per interactive or textual node with refs (`[e12] button "Save" disabled`), deterministic, with `--interactive-only`, `--depth`, `--region`, `--diff` (same refs, only what changed), `--max-tokens N` (viewport first, then the focus region, then the rest, and `… K more nodes`), repeated navigation collapsed, links shown relative to the page. Refs live until the document navigates; a stale ref is a one-line error with the fix.
   - Every verb returns a short structured result: what changed (url, title, navigated, dialog, console errors, network failures, downloads), not a dump; `then: diff` appends the page change to the action's own answer. Errors are one line, cause then hint. Every result carries `tokens` (bytes / 4); `budget: N` on any call cuts its longest text deterministically at a line boundary and says so.
   - `batch` runs many verbs in one request; steps with `after` are fork/join nodes that run concurrently and stream as they finish; it stops at the first failure unless told otherwise.
   - `find` and every `target` accept locators (`"Save"`, `role=button name~=Save`, `label~=`, `css=`, `testid=`) with auto-wait, so a model needs no CSS or XPath.
   - Page text is data: a snapshot withholds text that only a trick makes invisible or that reads like an instruction ("ignore previous instructions", white on white, a 1 px font, hidden alt text) and says how many; `traps` reports every kind apart from content (display none, offscreen, zero size, opacity 0, tiny font, low contrast, aria-hidden, HTML comments, injection-like attributes, meta tags, noscript, hidden frames, CSS content).
   - `--help-agent` is one page of at most 60 lines for a model's context; `atlas-drive mcp` is an MCP server on stdio (tools `drive_<verb>` with tight schemas, plus the tools a page declares through WebMCP as `page_<tool>`), in the style of `wol mcp`.
5. **Investigation verbs** for page reverse engineering and exploration over the same socket: `cdp`, `cdp_events` (filtered stream), `js` (scripts, source with pretty-print, search, break, paused, resume; stack frames mapped through source maps), `network` (log, bodies on demand, WebSocket frames, replay with edits, HAR), `route` (mock, block, delay), `css` (computed, matched rules, variables, `--why <property>`), `listeners`, `frameworks`, `storage` dump, `links`, `forms`, `extract`, `outline`, `webmcp`, `trace`, `memory`, `cursor show` (a virtual pointer drawn into screenshots) and `record` (frames).
6. **Permissions without spam.** Identity is `SO_PEERCRED` with a pinned `/proc/<pid>` (the scheme of atlas-bridge); only this account's processes are served. One consent per agent, by its executable path, with scopes `read` (page content), `act` (input, navigation, eval), `network`, `storage`, `files`; stored in `$XDG_CONFIG_HOME/wolos/atlas-drive/grants.json` (0600, replaced atomically), remembered, never asked per verb. The person at a terminal (the CLI on a tty) is not an agent; the CLI run by a program without a terminal is that program (its parent's executable). An unknown agent gets a one-line refusal that names the command that allows it; a shell sheet is a hook (`ATLAS_DRIVE_CONSENT_CMD`, asked once per new agent, exit 0 grants). **AUTO mode** is explicit and visible: `atlas-drive permissions auto on [--for 2h] [--site example.com]` (global or per site, time-boxed or until `auto off`) stops the questions; `permissions list` and `revoke <exe>` are the way back. Raw CDP needs every scope. While an agent is attached the daemon publishes `$XDG_RUNTIME_DIR/atlas/drive.attached` for the shell's indicator; a headed browser also shows the engine's own automation bar. CI (`ATLAS_DRIVE_CI=1`, the forge and the wolvm guest) skips consent.
7. **Round 2 (lead 2026-11-05 05:12Z, 05:40Z: every row under 500 ms, beat Playwright on every row, strip the snapshot to what a model needs).** Numbers in [bench/atlas-drive.md](../bench/atlas-drive.md), round 2.
   - **The accessibility mirror lives in the page, not in the browser's Accessibility domain.** Measured on the heavy page (2317 links): `Accessibility.getFullAXTree` costs the browser 820 to 990 ms on *every* call, warm or not and also with `Accessibility.enable` from the start (17 386 nodes, 6.9 MB, of which 3786 inline text boxes and 1756 list markers); `Accessibility.nodesUpdated` reports only nodes fetched level by level (`getChildAXNodes`), throttled to 250 ms in the engine. A mirror built from those events still pays the full tree once per document and lags a click by a quarter second. So `snapshot` (and every locator) runs one walk in Drive's own isolated world (`Page.createIsolatedWorld`, world `atlas-drive`; `src/mirror.rs`, `pagejs::SNAP`): roles from ARIA and the implicit HTML mapping, names from `aria-labelledby`, `aria-label`, labels, `alt`, `title` or content, the states the line grammar prints, visibility from `checkVisibility` (an element of opacity 0 stays in the tree, a styled checkbox is often one; its text is withheld), the trap checks on each text run by the element that shows it. It returns compact rows that become AX-shaped nodes, so the line builder, refs, diff and budget did not change. Element ids live in a WeakMap of that world while the document lives (refs stay stable across snapshots) and become backend node ids only when a verb acts on one (`Runtime.evaluate` in the world plus `DOM.describeNode`, cached per document). The page cannot reach the world's globals or its prototypes (an isolated world has its own JavaScript wrappers), and the walk does not change the DOM. This is not the in-page *agent* that decision 1 rejects: the protocol stays CDP, the script has no channel of its own and is read-only. `snapshot --ax` (and `ATLAS_DRIVE_AX=1`) keeps the browser's tree; refs differ between the two sources.
   - **Token diet of the snapshot** (full view only; the diff baseline keeps every line): a named link no longer prints its address (`--hrefs` does), an empty value and `unchecked` are not printed, a select prints its options with the chosen one starred and no value, a link with the same name and address as one already shown and a label text that repeats the control beside it are dropped, a run of ten or more same-shaped controls is folded to six and `… N more link like these (--full)`. Boilerplate seen on an earlier page stays collapsed; collapsing it on the second snapshot of the same page was not done, because the same page twice must give the same text (the diff relies on it).
   - **`--quiet [--fields a,b]`** on any verb returns only the answer (`value`/`text`, or the fields asked); a batch returns the answers of the steps that have one, a single answer bare.
   - **The browser is launched with `--disable-back-forward-cache`** (Playwright does the same): with the cache, the pages left behind stayed alive, in the same renderer when the site was the same, and the browser was 20 % bigger (1984 against 1649 MB) while every later click waited four times longer (32 against 7.7 ms).
   - A click at the point where the pointer already is sends no move event; `serve --launch` pre-warms the browser on a thread while the socket already answers; `memory` switches the Performance domain off after reading it; `goto` does not ask for the title of `about:` pages and says `retried` when the browser aborted its first attempt.
   - The frozen subset gains `Page.createIsolatedWorld` and `Performance.disable` (79 methods).
8. **Devtools** stay as the design decided (slim upstream frontend for Atlas; a WolOS inspector over this socket for the Rust-engine web apps, later). This record builds the shared piece, the daemon.

## Premortem (from the design, section 7, re-checked against what was built)
(a) The CDP subset broke at a Chromium major: the frozen list and its two-way scan, and verbs as the stable surface. Not yet generated from the engine's `.pdl`; the fixture is the sources themselves. (b) The consent flow made developers give up: remembered per executable, AUTO with a time box, CI mode, and no prompt per verb. (c) Deterministic screenshots flake: this record does not claim them; fonts and software raster are the lane's job and are not set by the daemon yet. (d) The Crystal shard lags: the socket is plain JSON lines, a shard is a thin client; not built. (e) A security review finds the socket reachable from a sandboxed app: it lives in the person's runtime directory, 0600, peer uid checked, and the WolOS sandbox must not mount that directory (to verify in the xguard and portal rules; not done here).

## Not decided here (honest list; docs/modules/atlas-drive.md has the per-verb status)
- Attaching to an Atlas that is already running: a pipe cannot be attached afterwards, so this needs the launcher to hold the pipe (the launcher flag `--atlas-drive`, Developer mode only) and hand the daemon the descriptors. Not built; today the daemon starts its own Atlas.
- The consent sheet itself (shell UI) and the indicator widget; the daemon provides the hook and the state file.
- Crystal shard, wolvm `drive.*` journey steps, generated bindings from `browser_protocol.pdl`, adapter for the page engine, video encoding (frames are written; muxing is ffmpeg's). An incremental mirror inside the page (a MutationObserver marking dirty subtrees, so a later snapshot re-walks only those) is not built: a full walk of the heavy page is already a fraction of the browser's own tree, and incremental state in the page is more surface for the page to probe.
- Cold start and the first visit after it are bound by the browser (start to first CDP reply 0.9 to 1.1 s, first renderer about 0.45 s in the component build); a pre-warmed daemon (`serve --launch` at session start) is how an agent avoids them.

## Consequences
- New crate in the workspace, new binary `atlas-drive`, new fuzz target `atlas_drive_wire` (STANDARDS list, ci.yml matrix, seeds), unsafe ratchet row `atlas-drive 0`, architecture row (`shared` only).
- The product launcher gains no debugging port. The Developer module will ship the binary (packaging not done here).
