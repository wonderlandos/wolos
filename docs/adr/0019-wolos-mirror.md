# 0019 - WolOS mirror: [wolos], [wolos-cachy], Arch
Status: accepted. Builds on 0016.
Context: pacman takes a package from the first repo that has it. We want our builds to win, x86-64-v3 builds of Arch packages where the CPU runs them, and one consistent release date for all of it. The upstream x86-64-v3 source (CachyOS repos `cachyos-v3`, `cachyos-core-v3`, `cachyos-extra-v3`) keeps no archive.
Decision:
- Order in `pacman.conf`: `[wolos]` (kernel, Hyprland, Flatpak, system, apps) -> `[wolos-cachy]` -> Arch `core`/`extra`/`multilib` at the release's archive date. Ours replace both; an optimized build replaces Arch's.
- `[wolos-cachy]` is a WolOS-hosted frozen copy made at release time by `image/repo/mirror-cachy.sh`: the dependency closure of `image/arch/packages.x86_64` + `desktop/packages.txt` + `image/repo/cachy-extra`, resolved in the Arch snapshot. A package is taken only if its upstream version equals the snapshot's (pkgrel may differ); otherwise Arch's stays. Each file is checked against the upstream database sha256 and signature (fingerprints in `image/repo/cachy-trusted`); the database is signed with the WolOS key, packages keep their upstream signatures, so the keyring package carries that key too.
- `wolos-mirrorlist` installs `/etc/pacman.d/wolos-mirrorlist`, included by `[wolos]` and `[wolos-cachy]`. Primary: GitHub release assets (`$repo-<date>` tags); more mirrors listed after it. `wol mirror rank` probes all in parallel and orders them by latency; `wol mirror status` shows them.
- CPU gate: `[wolos-cachy]` ships commented out. `wol mirror gate` (installer, first boot) turns it on only when `/proc/cpuinfo` covers x86-64-v3 (`wol_core::mirror::x86_64_level`). The installer then picks `linux-wolos-v3` when a repo offers it (same boot files as linux-wolos, which it replaces). v4/znver4 later.
- Release: the `v*` tag refreshes `[wolos-cachy]` (`iso.yml`) and publishes it as the `wolos-cachy-<date>` release. `release.json` names its revision (`cachy`). `wol update` moves the Arch date in `pacman.conf` and the date in `wolos-mirrorlist`, so all three repos move together.
Consequences: GitHub limits: 2 GiB per asset, 1000 assets per release; signatures travel inside the database so assets = packages + 4. Measured at 2026-10-20: 536 packages, about 1.0 GiB, largest 315 MiB. Epoch `:` in file names becomes `.` (assets cannot hold `:`). Roots only reach `[wolos]` packages' dependencies through the lists and `cachy-extra`.
