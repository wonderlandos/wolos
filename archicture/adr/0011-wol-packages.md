# 0011 - .wol packages: one signed file around a pkg(8) package
Status: accepted
Context: Many open-source desktop apps are not in FreeBSD pkg. Porting them by hand is slow; running Linux builds needs the Linux ABI. pkg(8) already resolves dependencies, tracks files, runs triggers and removes cleanly; a second file database would drift. `shared::bundle::Info` (`Info.json`, targets) already describes `.wol` bundles for `wol-run`.
Decision:
- A `.wol` file is a ustar archive with exactly these regular-file members, in order: `Info.json`, `icon.png` (optional), `payload.pkg` (a `pkg create` package, prefix `/usr/local`), `SHA256`, `SHA256.sig` (optional). Format: `archicture/modules/packages.md`.
- `SHA256` lists every other member as `SHA256 (<member>) = <hex>` (BSD `sha256`/`sha256sum --tag` lines, sorted). `SHA256.sig` is the raw 64-byte Ed25519 signature of the `SHA256` bytes.
- `Info.json` is `shared::bundle::Info` plus optional `name`, `summary`, `icon`, `categories`, `capabilities`, `package`. For a `.wol` file, target entries are relative to the payload prefix. The payload carries the same file as `share/wolos/packages/<id>/Info.json`: pkg owns the install record.
- Trust: Ed25519 public keys in `/usr/local/share/wolos/keys/*.pub` (PEM, `openssl pkey -pubout`). Signed by a trusted key: installs with the administrator password (5-minute cache applies). No signature: installs only as `unsigned` with a fresh password (never cached). A wrong hash, an unknown member or a signature no trusted key verifies: refused.
- wol-admind `wol-install <path> signed|unsigned` makes a restore point, copies the file into a root-only staging dir, verifies the copy, checks `pkg query -F` name and version against `Info.json`, installs the dependencies from FreeBSD pkg (`pkg install -y -A`), then `pkg add`s the payload. `wol-remove <id>`: `pkg delete -y <package>`, `pkg autoremove -y`.
- Repository: `.wol` files are GitHub Release assets of `github.com/wonderlandos/wol-packages`; `index.json` + `index.json.sig` (same key, same signature form) are served from its GitHub Pages site. The App Store and `wol search` read the index next to the curated pkg catalogue.
- Factory: `wol-packages` holds `recipes/<app>/recipe.toml`, the `wol-port` tool (draft a recipe from a git URL, emit the FreeBSD build script, pack, sign, index) and CI that builds changed recipes natively in a FreeBSD VM. Signing runs only when the `WOL_SIGNING_KEY` secret exists.
Consequences: Dependencies come only from FreeBSD pkg; a library pkg lacks must be ported or vendored first. No Linux ABI for ported apps. `.wol` apps are not in a pkg repository, so `pkg upgrade` leaves them alone: `wol update apps` compares them with the index. Capabilities are declared and shown before install; nothing enforces them yet. Producer (`wol-port`) and consumer (`wol_core::package`) are separate code bound by this format and a cross-checked fixture.
